## 3. 本次完成：M4 超时、托管与内存重连

### 3.1 目标

在不破坏 Room 单协程写模型的前提下，为每个回合增加超时事件；连续超时或断线后由服务端自动完成合法动作；玩家使用同一 token 建立新连接时换绑原座位，并立即恢复房间与私有牌局状态。

### 3.2 运行参数

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `UNO_TURN_TIMEOUT` | `20s` | 在线且未托管玩家的单回合时限 |
| `UNO_MANAGED_ACTION_DELAY` | `200ms` | 断线或托管玩家的自动行动延迟 |
| `UNO_TIMEOUT_STRIKE_LIMIT` | `2` | 连续超时达到该次数后进入持续托管 |

配置加载时要求三项均大于零，避免零值形成忙循环或关闭超时保护。

### 3.3 计时器与 mailbox

计时器回调不直接读取或修改 Room、Engine。每次排期生成递增 token，回调只向 mailbox 投递带 token 的内部命令；Room 消费命令时再次核对 token 与当前阶段，因此已经失效但来不及停止的旧定时事件不会影响新回合。

```
回合开始或当前玩家变化
  → 生成新 turn token 和截止时间
  → time.Timer 到期
  → Room.mailbox 内部事件
  → 核对 token、阶段和当前玩家
  → 执行自动动作并排期下一回合
```

服务端通过 `game_state.turn_deadline` 下发 UTC 截止时间。补喊或抓 UNO 不会刷新当前回合时限，防止用非回合动作无限续期。

### 3.4 自动行动策略

| 场景 | 自动动作 |
|------|----------|
| 有累计罚牌 | 接受并摸取全部罚牌 |
| 正常回合且存在合法牌 | 随机选择一张合法牌并同步喊 UNO |
| 正常回合且无合法牌 | 摸牌；若新牌可出则立即打出 |
| 摸牌决策阶段 | 新牌可出则打出，否则过牌 |
| 万能牌选色阶段 | 从四种有效颜色中随机选择 |

在线玩家单次超时只增加连续超时次数；达到阈值后标记为托管，后续回合使用较短的托管延迟。玩家成功执行回合动作或重连后会清零该状态。

### 3.5 断线、占座与换绑

- 等待阶段断线沿用成员移除语义；对局中断线则保留座位、手牌和引擎顺序，并立即进入托管。
- 新连接完成 hello 后，RoomManager 按 token 中的玩家身份查找原房间，并在 mailbox 内替换成员 Session。
- 换绑完成后依次下发最新 `room_state` 和仅该玩家可见的完整 `game_state`，当前玩家同时获得新的完整回合时限。
- 当前行动者断线或换绑会重排计时器，其他在线玩家同步收到新 `game_state`，保证各端展示同一截止时间。
- 如果旧连接仍存活，先完成换绑再异步关闭；旧连接迟到的消息和断线事件均通过 Session 指针校验丢弃。
- 对局中主动离开会解除玩家到房间的路由，但保留幽灵座位托管至终局，避免破坏 Engine 的固定座位结构。
- 出站队列满时异步关闭慢连接，避免 Room actor 在断线回调同步回投自身形成死锁。

### 3.6 验收结果

- [x] 定时器仅投递内部事件，所有 Room 与 Engine 状态仍在 mailbox 内修改
- [x] 连续超时达到阈值后进入托管，并可自动完成一整局
- [x] 当前玩家断线后保留座位并继续自动行动
- [x] 同 token 重连后恢复成员在线状态、私有手牌与回合截止时间
- [x] 新 Session 可以继续执行原座位的合法动作，旧 Session 不会覆盖新状态
- [x] 出站背压关闭不会阻塞 Room actor
- [x] 超时托管与重连端到端用例连续执行 20 次通过
- [x] `go test ./...` 与 `go vet ./...` 通过

### 3.7 后续边界

M4 的房间、token 和重连映射仍只存在于单进程内存中，进程重启后不会恢复。本阶段不在回合热路径写数据库；下一阶段 M5 仅落地玩家、对局与结算三类持久记录，房间快照和重启恢复继续留到 M6。

## 4. 后续阶段摘要

### M1 房间（已完成）

| 交付 | 要点 |
|------|------|
| RoomManager | roomId → Room |
| Room mailbox | 单协程串行 |
| 消息 | create_room / join_room / leave / ready / start（仅校验人数与准备，可暂不真正开牌） |
| 广播 | 成员列表、准备状态 |
| 日志 | 每条房间相关 WS 消息一条 |

**验收：** 2～3 客户端同房状态一致。

### M2 规则引擎（已完成）

| 交付 | 要点 |
|------|------|
| `internal/game/uno` | 牌堆、合法性、叠罚、Reverse/Skip、结算 |
| 单测 | 表驱动覆盖主路径与边界 |
| 无 IO | 不依赖 session/room/store |

**验收：** `go test ./internal/game/uno/...` 绿。

### M3 联调一局（已完成）

Room 开局创建 Engine；出牌/摸牌/选色/UNO；私有手牌 vs 公开桌面；非法操作拒绝。  
**验收：** 2 人手打完一局。

### M4 超时与重连（内存，已完成）

回合定时器事件进 mailbox；断线占座 + 托管；重连全量快照。  
**验收：** 拔线再连能续打。

### M5 MySQL（下一步）

`players` / `matches` / `match_results`；登录写 players；开局/结算写库。  
**验收：** 局后库中有记录。

### M6 Redis 重启

token 会话；房间快照；启动加载；优雅退出刷盘。  
**验收：** kill -9 后拉起，原 token 重连续打。

### M7 打磨

空房回收、指标可选、日志字段统一、README 使用说明。

## 5. 编码与质量约定（全程）

| 项 | 要求 |
|----|------|
| 注释 | 非测试 Go 代码函数级注释；复杂逻辑块级/行级 |
| 日志 | 仅边界打点（HTTP 中间件 / WS 消息结束）；`WithContext` |
| 错误 | `errors.Is` / `fmt.Errorf("%w")` |
| 依赖方向 | `session/room → game`；`game` 不依赖网络与 DB |
| 单文件 | 尽量 < 500 行，函数 < 50 行 |
| 测试 | 新公共能力尽量有单测；规则包覆盖优先 |

## 6. 风险与顺序纪律

| 风险 | 规避 |
|------|------|
| 过早上房间+规则 | 先 M0-b 管道再 M1 再 M2 |
| 出牌写 DB | 禁止；仅结算写 MySQL |
| 在 Room 协程里直接 Write WS | 只投递 session.send |
| 无 trace 刷屏日志 | 中间路径不打访问日志 |

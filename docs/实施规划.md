## 3. 下一步详细规划：M0-b WebSocket 会话

### 3.1 目标

玩家用登录拿到的 `token` 建立 WebSocket；服务端鉴权成功后下发身份确认；支持心跳；为 M1 房间消息预留统一协议外壳。

### 3.2 非目标

- 房间、准备、出牌  
- 重连占座、托管  
- MySQL / Redis  
- 同一 player 多连接踢旧连（可简单实现「后连踢前」，可选）

### 3.3 协议草案（JSON）

统一外壳：

```json
{
  "type": "ping",
  "request_id": "可选，客户端生成，用于对应响应",
  "payload": {}
}
```

| 方向 | type | payload | 说明 |
|------|------|---------|------|
| S→C | `hello` | `{ "player_id", "nickname" }` | 鉴权成功后首包 |
| C→S | `ping` | 可空 / `{ "t": 客户端时间戳 }` | 心跳 |
| S→C | `pong` | 回显或 `{ "t": ... }` | 心跳响应 |
| S→C | `error` | `{ "code", "message" }` | 业务/协议错误（连接可继续或按 code 断开） |

**鉴权方式（写死）：**  
`GET /ws?token=<token>` 升级时校验；失败返回 HTTP 401，不升级。

**日志：**  
每个入站消息处理结束一条：`msg=ws message`，字段含 `type`、`player_id`、结果；带独立或连接级 `trace_id`（建议：每消息 `NewTraceID`，或连接建立时一个 conn_trace + 每消息 msg_id；**推荐每消息一个 trace_id**，与「一包一条」一致）。

### 3.4 模块与文件

| 文件 | 职责 |
|------|------|
| `go.mod` | 增加 `gorilla/websocket` |
| `internal/protocol/message.go` | Envelope、类型常量、编解码辅助 |
| `internal/protocol/errors.go` | 协议错误码常量（可选） |
| `internal/session/session.go` | Session 结构、readPump、writePump、Send |
| `internal/session/manager.go` | 可选：按 player_id 登记连接 |
| `internal/server/ws.go` | 升级、鉴权、创建 Session、启动泵 |
| `internal/server/server.go` | 注册 `GET /ws` |
| `internal/config` | 可选：读/写缓冲、ping 周期配置 |

### 3.5 Session 运行时模型

```
Upgrade + Authenticate
    → New Session { conn, playerID, nickname, send chan(64) }
    → go writePump   // 只从 send 写 conn
    → go readPump    // 读消息 → 解析 Envelope → 处理
    → 入站首推 hello（经 send）

readPump:
  for {
    read frame
    ctx = IntoContext(..., NewTraceID())
    switch type {
      case ping: enqueue pong
      default: enqueue error unknown_type
    }
    logger.WithContext(ctx).Info/Warn("ws message", ...)
  }
  // 退出：关闭 send、unregister

writePump:
  for msg := range send { WriteMessage }
```

约束：

- **禁止**在 readPump 里阻塞 `conn.Write`（一律进 `send`）  
- `send` 满：断开连接（背压策略，简单粗暴）  
- 使用 `errors` 包装读/写/鉴权错误  

### 3.6 实现步骤（建议顺序）

1. **protocol**：Envelope + Marshal/Unmarshal  
2. **session**：Session + 双泵 + Send 非阻塞/满则关  
3. **ws handler**：token 查询参数、升级、hello  
4. **注册路由** + 配置（可选）  
5. **测试**：protocol 单测；session 可用 `httptest` + gorilla 的 Dialer 或最小集成测  
6. **手测**：登录 → wscat/websocat 连 → ping  

### 3.7 验收清单

- [ ] 有效 token 升级成功，收到 `hello`  
- [ ] 无效/缺失 token → 不升级（401）  
- [ ] `ping` → `pong`  
- [ ] 未知 type → `error`，连接策略明确（建议不断开）  
- [ ] 每条入站消息结束 **恰好一条** 带 `trace_id` 的日志  
- [ ] 客户端断开，服务端泵退出无泄漏（可用短压测观察 goroutine）  
- [ ] `go test ./...` 通过  

### 3.8 预估

约 0.5～1 天。

## 4. 后续阶段摘要

### M1 房间（M0-b 之后）

| 交付 | 要点 |
|------|------|
| RoomManager | roomId → Room |
| Room mailbox | 单协程串行 |
| 消息 | create_room / join_room / leave / ready / start（仅校验人数与准备，可暂不真正开牌） |
| 广播 | 成员列表、准备状态 |
| 日志 | 每条房间相关 WS 消息一条 |

**验收：** 2～3 客户端同房状态一致。

### M2 规则引擎

| 交付 | 要点 |
|------|------|
| `internal/game/uno` | 牌堆、合法性、叠罚、Reverse/Skip、结算 |
| 单测 | 表驱动覆盖主路径与边界 |
| 无 IO | 不依赖 session/room/store |

**验收：** `go test ./internal/game/uno/...` 绿。

### M3 联调一局

Room 开局创建 Engine；出牌/摸牌/选色/UNO；私有手牌 vs 公开桌面；非法操作拒绝。  
**验收：** 2 人手打完一局。

### M4 超时与重连（内存）

回合定时器事件进 mailbox；断线占座 + 托管；重连全量快照。  
**验收：** 拔线再连能续打。

### M5 MySQL

`players` / `matches` / `match_results`；登录写 players；开局/结算写库。  
**验收：** 局后库中有记录。

### M6 Redis 重启

token 会话；房间快照；启动加载；优雅退出刷盘。  
**验收：** kill -9 后拉起，原 token 重连续打。

### M7 打磨

空房回收、指标可选、日志字段统一、README 使用说明。

## 5. 编码与质量约定（全程）

| 项 | 要求 |
|----|------|
| 注释 | 非测试 Go 代码函数级注释；复杂逻辑块级/行级 |
| 日志 | 仅边界打点（HTTP 中间件 / WS 消息结束）；`WithContext` |
| 错误 | `errors.Is` / `fmt.Errorf("%w")` |
| 依赖方向 | `session/room → game`；`game` 不依赖网络与 DB |
| 单文件 | 尽量 < 500 行，函数 < 50 行 |
| 测试 | 新公共能力尽量有单测；规则包覆盖优先 |

## 6. 风险与顺序纪律

| 风险 | 规避 |
|------|------|
| 过早上房间+规则 | 先 M0-b 管道再 M1 再 M2 |
| 出牌写 DB | 禁止；仅结算写 MySQL |
| 在 Room 协程里直接 Write WS | 只投递 session.send |
| 无 trace 刷屏日志 | 中间路径不打访问日志 |
